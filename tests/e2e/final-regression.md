без 1С, Битрикс24, реальных данных компании и платных вызовов LLM.

Стабильность. Промежуточный прогон шёл параллельно с `hk check` и дал одно падение нового теста «API недоступен при

Это поведение продукта, а не дефект. Тест теперь нажимает «Повторить», если ошибка ещё на экране, и в обоих случаях
проверяет, что данные загрузились. После правки этот тест прошёл 15 раз подряд, весь `final-regression.spec.mjs` —
3 раза подряд (42 passed), полный набор — 2 раза подряд (выше).

## ИИ без ключа и без внешней сети

- `ANTHROPIC_API_KEY` пустой, запросы браузера к `api.anthropic.com` заблокированы, любые запросы браузера
  за пределы `127.0.0.1`/`localhost` фиксируются и должны отсутствовать.
- `GET /complaints/suggest-category`: 200, `source` ∈ {`demo-fixture`, `rules`, `none`} по `contracts/api.yaml`
  (`CategorySuggestion.source`), никогда `llm`; бейдж в UI соответствует источнику («Демо ИИ» / «Правила (без ИИ)»).
- `GET /summary/digest` (руководитель и администратор): 200, `source=template`, бейдж «Шаблон (без ИИ)».
- `GET /analytics/trends`: 200 и форма ответа (`totals`, `byDay`); поле `source` не требуется — его нет в контракте.
- Сбой подсказки категории или сводки не блокирует подачу и не ломает дашборд; «Повторить» восстанавливает сводку.
- Перевод без ключа честно отвечает 503 «Перевод сейчас недоступен» — `ux-release` тест 1.

## Console и network

Тест `final-regression` «console и network» проходит экраны трёх ролей (мои обращения, карточка, форма с похожими
обращениями, очередь, карточка руководителя, дашборд, сводка) и собирает ошибки console, `pageerror`,
`requestfailed`, ответы ≥ 400 и внешние запросы. Итог классификации:

| Класс | Найдено на основном пути |
|---|---|
| Ошибки console / исключения страницы | 0 |
| Ответы 4xx/5xx | 0 |
| Неудавшиеся запросы | 0 |
| Внешние запросы (вне локального стенда) | 0 |
| Ожидаемые отказы вне основного пути | `POST /translations` → 503 без ключа (`ux-release`); тайлы OpenStreetMap блокируются в тесте карты (`ux-release`) |

Ошибки, сымитированные в изолированных тестах (`route.abort`/`fulfill`), относятся к классу «ожидаемые» и проверяются там же.

## Найденные дефекты

**D1. Черновик формы подачи теряется без предупреждения.** Новый, задача на продукт пока не заведена.
Шаги: роль «Сотрудник» → «Новое обращение» → выбрать категорию и ввести описание → нажать в меню «Мои обращения»
→ снова «Новое обращение». Ожидается предупреждение об уходе или восстановленный черновик; фактически поля пустые,
предупреждения нет (`web/src/pages/SubmitPage.tsx` хранит поля только в состоянии компонента).
Тест: `final-regression.spec.mjs` «уход с заполненной формы подачи…» помечен `test.fixme`; снять пометку после исправления.

## Артефакты при падении

По умолчанию трейс и скриншоты выключены — этого требует приёмка #133 (`tests/acceptance/133-e2e-extended-demo.test.mjs`),
её мы не меняем. Для сбора артефактов есть `npm --prefix tests/e2e run e2e:artifacts` (то же, что
`playwright test --trace on`). При падении в `tests/e2e/test-results/<тест>/` остаются `trace.zip`,
`test-failed-1.png` и `error-context.md`; это проверено на временно падающем тесте. Просмотр:
`npx playwright show-trace <путь>/trace.zip`. В CI дополнительно пишется HTML-отчёт `playwright-report/`.
Порядок при падении: перезапустить с `e2e:artifacts`, приложить trace и скриншот, записать шаги из `test.step` упавшего теста.

## Пересечения с #154

#154 («демо не падает без ключа и сети») — приёмочные тесты API через `buildApp`/`inject` в `tests/acceptance/`;
к моменту прогона не реализована. Здесь использованы её уточнённые критерии К1 (источники трёх эндпоинтов по
контракту) и К4 (демо-путь без сети), но на уровне браузера: e2e не подменяет `fetch` в процессе API и не
проверяет логи на утечку ключа (К2, К3, К5 остаются за #154).
