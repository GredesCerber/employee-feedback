# E2E: демо-путь

Один сквозной тест Playwright (`demo-path.spec.mjs`) проходит все 6 шагов сценария демо из
[docs/tz-analysis.md](../../docs/tz-analysis.md) на синтетических данных, без ручных действий:

1. Сотрудник подаёт обращение (тип, категория, описание, решение, тестовое вложение) и получает номер `A-0XX`.
2. Ответственный назначается по категории; обращение в категории без правила попадает в запасную очередь, руководитель назначает его вручную.
3. Руководитель начинает рассмотрение и запрашивает уточнение, автор отвечает, ответ виден в карточке.
4. Одно обращение закрывается решением «Реализовано», другое — мотивированным отказом; автор видит итог и объяснение.
5. Руководитель фильтрует по подразделению, категории, статусу, сроку и находит просроченные.
6. Администратор открывает сводку: всего, доля закрытых, среднее время первого ответа, типы, повторяющиеся темы.

Каждый прогон создаёт свои обращения с уникальной меткой `[e2e-…]`, поэтому тест не зависит от того,
что уже лежит в памяти API.

## Запуск на чистой машине

Нужны Node.js 22.12+ и npm. Из корня репозитория:

```sh
npm --prefix api ci
npm --prefix web ci
npm --prefix tests/e2e ci
npm --prefix tests/e2e run e2e:install   # один раз: браузер Chromium для Playwright
npm --prefix tests/e2e run e2e
```

Playwright сам собирает и запускает API на `http://127.0.0.1:3000` и фронтенд Vite на
`http://127.0.0.1:5173`, а после прогона останавливает их. Если на этих портах уже работают API и
фронтенд из этого репозитория, они переиспользуются (кроме `CI=1`, где порты должны быть свободны).

Против уже поднятого стенда (например, `docker compose up`, фронтенд на 8080):

```sh
E2E_BASE_URL=http://localhost:8080 npm --prefix tests/e2e run e2e
```

Посмотреть прогон глазами: `npm --prefix tests/e2e run e2e:headed`. При падении в
`tests/e2e/test-results/` сохраняются скриншот и trace (`npx playwright show-trace <путь>`).

## Ограничения

- Шаг 5 опирается на сроки синтетического набора (08.11.2026): к дате демо эти обращения просрочены.
- Браузер работает в часовом поясе `Asia/Omsk` и локали `ru-RU`, чтобы фильтр по дате был воспроизводим.
- Данные API живут в памяти; перезапуск API возвращает исходные 20 обращений.
