# Рабочий цикл hk

Инструменты доступны двумя способами — выбирай любой, результат одинаковый:
- MCP: `hk_task_next`, `hk_task_claim`, `hk_check`, `hk_commit`, `hk_pr_open`, `hk_task_status`, `hk_task_release`, `hk_status`
- CLI: `hk task next`, `hk task claim <id>`, ... (вывод JSON при запуске не из терминала)

Цикл запускают так: `/loop 10m Работай по циклу hk-workflow` (Claude Code) — агент сам проверяет очередь раз в 10 минут.

## Шаги
0. **Сначала команда.** `hk task next` смотрит не только задачи. `artifacts.kind`:
   - `fix` — твой PR ждёт тебя (правки ревьюера, красный check, конфликт с main): вернись в worktree задачи, исправь, `hk check` → `hk commit` → `hk pr open` (запушит в тот же PR), потом снова `hk task next`;
   - `merge` — готовый PR `risk:high` (ревью и проверки зелёные): `gh pr merge <n> --merge --delete-branch`, потом снова `hk task next`;
   - `review` — PR ждёт твоего ревью: навык `hk-review` → `hk pr review <n> --verdict approve|changes --note "..."`, потом снова `hk task next`;
   - `task` — задача, дальше шаг 1. Сначала выдаются задачи твоей зоны (назначены на твоего человека в блоке `hk-team`); чужую — только если своих нет.
1. **Взять.** `hk task claim <id>`. Перейди в `artifacts.worktree`.
2. **Понять.** `gh issue view <id>`. Выпиши критерии приёмки. Если хоть один нельзя проверить тестом — `hk task status <id> needs-spec --note "вопрос"` и стоп.
3. **Тесты сначала.** Напиши падающие тесты по каждому критерию. LLM и внешние API — через фикстуры.
4. **Реализация.** Минимально, в пределах своей зоны и контракта.
5. **Проверка.** `hk check`. Красное → читай `error.cause_hint`, исправляй, повторяй. Длинная задача → `hk task heartbeat <id>` раз в ~30 мин.
6. **Сдача.** `hk commit -m "feat: ..."` → `hk check` → `hk pr open`.
7. **Дальше.** `hk task next`.

## Капитан (зона `review` в hk-team)
- Ревью и мерж приходят тебе первыми через `hk task next` — не откладывай их: пока PR не смержен, задачи за ним ждут.
- Раз в цикл — `hk status`: `blocked` и `needs-spec` разбери сам (ответь в issue и верни в очередь: `hk task release <id> --force --note "ответ: ..."`, или добавь задачу в PRD для нужной зоны и `hk kickoff --apply`); PR, ждущие дольше 30 минут, — ревью сам или напиши людям.
- План (ТЗ, PRD, kickoff) делает только капитан. Участник, которого просят спланировать, отвечает: «план делает капитан».

## Стоп-условия
| Ситуация | Действие |
|---|---|
| Та же ошибка 3 раза | `hk task status <id> blocked --note "..."` |
| Нужно менять контракт/чужую зону | `blocked` с описанием |
| Не справляюсь | `hk task release <id> --note "что успел"` |
| Открыт issue `hk:pause` | закончить шаг, остановиться |
| `claim_conflict` 3 раза подряд | остановиться, сообщить человеку |
