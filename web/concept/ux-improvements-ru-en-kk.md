## UX-01. Контракт необязательного местоположения

Зона: contracts. Исполнитель: агент контрактов капитана. Зависимости: нет.
Файлы: contracts/api.yaml.

Добавить необязательный объект location с latitude и longitude в CreateComplaint и Complaint. Согласовать поведение отсутствующего поля, валидацию и сериализацию. Предлагаемая семантика: поле отсутствует, когда пользователь не выбрал точку; null не используется. latitude: конечное число от -90 до 90; longitude: от -180 до 180. Дополнительные поля объекта запрещены. Существующие записи без location остаются валидными. Геоданные не кодируются в description/proposedSolution.

Критерии:

- Given старый запрос без location When валидирую по обновлённой схеме Then запрос допустим.
- Given точка на границах диапазонов When валидирую запрос Then latitude/longitude допустимы и описаны в ответе Complaint.
- Given пропущенная координата, строка, null, неизвестное поле или выход за диапазон When валидирую Then запрос отклонён.
- Given изменённый контракт When генерирую клиент штатным скриптом Then новые типы выводятся без ручной правки schema.d.ts.

Зона: api. Исполнитель: агент API капитана. После: UX-01 и отдельные независимые приёмочные тесты.
Файлы: api/src/model.ts, complaints.ts, persistence.ts, pg-persistence.ts по необходимости; api/test/.

Сохранять location из валидированного запроса и возвращать в карточке. Учесть JSON/JSONB-хранилище, перезапуск и совместимость со старыми записями. Использовать существующие проверки доступа, не передавать координаты в AI-классификацию и сводку.

Критерии:

- Given неверные координаты When отправляю запрос Then получаю контрактную ошибку и запись не создаётся.
- Given чужое обращение сотрудника When запрашиваю карточку Then действующая проверка доступа не раскрывает ни обращение, ни location.

## UX-03. Необязательная интерактивная карта

Зона: web. Исполнитель: агент карты. После: UX-01, UX-02, UX-08; UI можно разрабатывать против контрактных моков после UX-01.
Файлы: web/src/pages/SubmitPage.tsx, ComplaintPage.tsx; новый компонент карты и его CSS; web/package.json и lock-файл при добавлении зависимости; web/tests/; сгенерированный schema.d.ts.

Добавить сворачиваемое «Указать место на карте — необязательно». Реальная карта с масштабированием и перемещением, установка одной метки, её перенос и удаление. Подключение библиотеки и провайдера тайлов оформить в задании; учитывать лицензию/атрибуцию. Карта загружается лениво после открытия блока. Без автоматического запроса геолокации. Доступная альтернатива выбору мышью — подписанные поля координат с валидацией и подтверждением. На карточке показывать выбранную точку. Все подписи через ru/en/kk.

Критерии:

- Given карта не открывалась When отправляю валидное обращение Then оно создаётся без location.
- Given выбрана точка When передвигаю или удаляю метку Then состояние формы и отправляемый location соответствуют последнему действию.
- Given карта/тайлы недоступны When заполняю остальную форму Then обращение можно отправить; нет поддельной карты или обещания сохранённой точки.
- Given управление клавиатурой When использую поля координат и удаление Then можно выбрать/очистить точку без мыши и без ловушки фокуса.
- Given отправка не удалась When исправляю форму и повторяю Then выбранная точка сохраняется до успешной отправки или явного удаления.
- Given анонимная подача с точкой When подтверждаю отправку Then вижу краткое объяснение, что точное место может косвенно указать на автора; карта остаётся необязательной.

## UX-04. Вернуться к последнему открытому обращению

Зона: web. Исполнитель: агент навигации. Зависимости: нет; интеграция строк после UX-08.
Файлы: web/src/features/lastComplaint.ts (новый), ComplaintPage.tsx, App.tsx или MyComplaintsPage.tsx/QueuePage.tsx; web/tests/.

Трактовка: последнее успешно открытое обращение сотрудника или руководителя. Запоминать только ID после успешной загрузки карточки, раздельно для пользователя и роли; не сохранять описание, комментарии или номер обращения. Использовать demoUsers[role] из session.tsx как идентификатор текущей демо-сессии. Кнопка/ссылка «Вернуться к последнему обращению» доступна из списка; на самой этой карточке не дублируется. Сохранение локальное для этого браузера. Существующее сохранение текущей карточки при смене роли (#203) продолжает работать.

Критерии:

- Given успешно открыта карточка When ухожу в список и нажимаю возврат Then открывается последняя карточка в маршруте текущей роли.
- Given сохранён ID When перезагружаю страницу Then возврат работает для того же пользователя и роли.
- Given другой пользователь или роль When открываю список Then чужая сохранённая ссылка не показывается.
- Given сохранённый ID недоступен/удалён When пытаюсь вернуться Then 403/404 очищает указатель и показывает понятное состояние без раскрытия чужих данных.
- Given временный сетевой сбой When проверяю указатель Then есть повторная попытка; сетевой сбой не считается удалением обращения.
- Given localStorage недоступен или содержит повреждённый JSON When открываю приложение Then приложение работает с памятью текущей сессии без исключения.

Файлы: web/src/shell.css, pages.css, pages/{complaint,dashboard,summary}.css, features/weeklyDigest.css; web/tests/. Если нужны новые токены — отдельная задача design, без правок чужой зоны.

Оформить единым стилем input, textarea, select, поиск, фильтры, выбор роли, темы и языка, поля действий руководителя, будущие поля карты. Чёткие label, hover, focus-visible, invalid, disabled/read-only; цельная высота, внутренние отступы, скругления, аккуратная граница. Сохранить нативные элементы и семантику. - Given длинный русский/английский/казахский текст When рендерю заголовки, кнопки и списки Then подписи не обрезаются до потери смысла.
- Given применены стили When запускаю существующие tokens/a11y/author/manager tests Then проверки контраста и действий проходят.

- Given открыты уведомления When нажимаю Escape Then панель закрывается с корректным возвратом фокуса.
- Given запуск проверки CSS When анализирую изменения Then нет transition: all и постоянного will-change на всей странице.

## UX-10. Контракт перевода текста сообщения

Зона: contracts. Исполнитель: агент контрактов капитана. Зависимости: нет.
Файлы: contracts/api.yaml.

Зафиксировать endpoint перевода с locale allowlist ru/en/kk, ограничениями длины/размера, проверкой сессии, rate limit и безопасными ошибками. Рекомендуется ресурсный путь /complaints/{complaintId}/translations с полем выбора description/proposedSolution/comment/decision и commentId при необходимости: сервер сначала проверяет доступ к обращению и извлекает конкретный текст, провайдеру передаётся только этот текст и язык. Не принимать произвольные URL/команды. Ответ: translatedText, targetLocale, provenance. Оригинал и Complaint не изменяются. При отсутствии провайдера — 503 TRANSLATION_UNAVAILABLE. Неправильная цель/отсутствующее поле — контрактная ошибка. Для чужого обращения действующее сокрытие существования через 404.

Критерии:

- Given допустимый запрос When проверяю схему Then поле-источник и целевой язык однозначно определены.
- Given недопустимый locale/источник/идентификатор When проверяю запрос Then описана явная ошибка без вызова провайдера.
- Given перевод недоступен When читаю контракт Then невозможен ответ с оригиналом под видом успешного перевода.

## UX-11. Серверный перевод через существующий AI runtime

Зона: api. Исполнитель: агент API капитана. После: UX-10 и отдельные независимые приёмочные тесты.
Файлы: api/src/ai/provider.ts, ai/anthropic.ts, новый route перевода, app.ts; api/test/ и фикстуры.

В актуальном origin/main уже есть AiProvider, ANTHROPIC_API_KEY/AI_MODEL, timeout и injectable fetch. Добавить отдельную операцию translate; не использовать локальные fallback классификатора/сводки как перевод. Перед провайдером проверить видимость обращения и выбранного комментария, запрос не должен раскрывать анонимного автора. Ограничение входа, timeout, rate limit; текст из сообщения трактовать как данные. Не логировать текст и секреты. Без ключа вернуть контрактное состояние недоступности, ни одного сетевого запроса. Тесты через фикстуры/injected fetch.

Критерии:

- Given доступный текст и настроенный провайдер When перевожу Then ответ соответствует схеме, оригинальный объект и история не меняются.
- Given нет ключа, timeout или некорректный ответ When вызываю перевод Then клиент получает безопасную контрактную ошибку без ложного перевода.
- Given обращение/комментарий недоступны When вызываю перевод Then доступ отклонён до вызова внешней модели.
- Given внешнему провайдеру отправлен запрос When проверяю тело Then там только выбранный текст, целевой язык и инструкция перевода; нет автора, ID, остальных комментариев или вложений.
- Given запускаю тесты When имитирую успех/сбой Then сеть не используется и секреты не попадают в логи/ответ.

Критерии:

- Given исходное сообщение When жму перевод Then вижу loading, затем явно помеченный перевод и могу показать оригинал.
- Given провайдер недоступен When запрос завершается ошибкой Then оригинал виден, есть локализованная ошибка и повторная попытка.
- Given меняю карточку или язык во время запроса When старый ответ приходит Then он не попадает в новую карточку/язык.
- Given ответ содержит HTML-подобный текст When показываю перевод Then разметка не исполняется.
- Given пользователь ничего не нажимал When открываю карточку Then переводы автоматически не запрашиваются.

## UX-13. Независимые проверки и приёмка

Зона: e2e. Исполнитель: отдельный QA-агент, не автор соответствующей реализации.
Файлы: новые tests/pending/<T>/ для парных задач risk:high и новые E2E в tests/e2e/; существующие приёмочные тесты сохраняются без изменений.

Капитан определяет risk для каждой новой задачи и создаёт отдельную tests_for для каждой risk:high, как требует hk. Парные тесты пишутся до реализации; данный сводный QA-пункт не заменяет эти задачи. На фронтенде полезные существующие проверки: a11y, tokens, role-switch-card, notifications, submit-assist, undo-action, weekly-digest, author, manager.

Обязательные сценарии:

1. Подача без карты; подача с точкой; перемещение/очистка; недоступные тайлы; сохранение после перезапуска API.
2. Возврат после навигации/reload; разделение по пользователю/роли; stale ID; 403/404; временный сетевой сбой.
3. Все формы в light/dark; ширина 360/768/1440; увеличение 200%; Tab/Escape; видимые ошибки и фокус.
4. reduced-motion и отсутствие потери символов/IME при наборе; отсутствие заметного сдвига страницы при анимации.
5. ru/en/kk на всех ролях; язык после reload; числа/даты/множественные формы; длинные переводы.
6. Перевод выбранного сообщения, показ оригинала, сбой/нет ключа, гонка запросов, недоступное чужое обращение, отсутствие побочного изменения Complaint.
7. Действующий полный демо-путь: подача → назначение → уточнение → решение → фильтры → сводка.

## Порядок запуска и исключение конфликтов

- Можно независимо начать контракт карты (UX-01), контракт перевода (UX-10), CSS/читаемость (UX-05) и основу языков (UX-08). Два задания contracts/api.yaml выполняются по очереди.
- UX-05 → UX-06 → UX-07: один агент оформления и последовательные PR для общих CSS-файлов.
- UX-08, UX-04, UX-07 меняют App.tsx: интеграция последовательно; помощникам не выдавать этот файл одновременно.
- UX-03 меняет SubmitPage/ComplaintPage: завершить его интеграцию до миграции строк этих страниц в UX-09. Карта/resume могут использовать подготовленные i18n-ключи с UX-08.
- UX-09 затрагивает много страниц: после интеграции карты дополнить локализацию её строк; затем UX-12. Новый текст принимается только с ключами всех трёх языков.
- Задачи API карты и перевода выполняются в разных worktree, без одновременной правки app.ts/model.ts; API контракты вливаются первыми.
- Каждый PR — одна hk-задача; полный hk check; затем независимое ревью. Тесты внешних сервисов без сети.
