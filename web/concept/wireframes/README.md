# Низкодетальные макеты ключевых экранов

Задача #11, требование R10. Макеты построены по [карте экранов](../../../design/flows/screen-map.md) (#8) и [сценарию демо](../../../docs/tz-analysis.md). Это схемы без логики: расположение блоков, подписи кнопок и переходы. Цвета, шрифты и иконки — в зоне дизайна.

Тест `tests/acceptance/11-wireframes.test.mjs` проверяет, что макет есть у каждого узла карты и что переходы в разделах «Переходы» совпадают со стрелками карты.

| Макет | Маршрут | Роль | Шаги демо |
|---|---|---|---|
| [Демонстрационная роль (общая шапка)](roles.md) | шапка | employee, manager, admin | все шаги: смену роли делает ведущий |
| [Мои обращения](mine.md) | `/my` | employee | 1, 3, 4 |
| [Новое обращение](submit.md) | `/submit` | employee | 1, 2 |
| [Обращение зарегистрировано (состояние формы)](registered.md) | `/submit` | employee | 1 |
| [Карточка автора](author.md) | `/my/:complaintId` | employee (автор обращения) | 1, 2, 3, 4 |
| [Очередь обращений](queue.md) | `/queue` | manager | 2, 5 |
| [Карточка руководителя](handling.md) | `/queue/:complaintId` | manager | 2, 3, 4, 5 |
| [Сводка](summary.md) | `/summary` | admin | 6 |
| [О прототипе](about.md) | `/about` | employee, manager, admin | вне шагов, для вопросов жюри (R12) |

## Путь по шагам демо

1. `submit` → `registered` → `author`: сотрудник подаёт обращение и видит номер.
2. `author` (ответственный и срок) и `queue` с фильтром «Без ответственного» → `handling`: ручное назначение.
3. `handling` (запрос уточнения) → смена роли → `mine` → `author` (ответ).
4. `handling` (решение и отказ) → смена роли → `author` (итог и объяснение).
5. `queue` (фильтры, «Только просроченные») → `handling`.
6. Смена роли на администратора → `summary`.
