# Фронтенд

Node.js 22.12+ и npm. Из корня репозитория:

```sh
npm --prefix web ci
npm --prefix web run test
npm --prefix web run build
npm --prefix web run dev
```

Vite открывает приложение на http://localhost:5173. Dev-прокси передаёт `/api/*` на `http://localhost:3000/*`; путь контракта `/complaints` остаётся `/complaints` на сервере. Для другой среды задайте `VITE_API_BASE_URL` (без завершающего `/`). В production нужен прокси `/api` и fallback маршрутов приложения на `index.html`; `vite preview` предназначен только для локальной проверки сборки.

Каркас #50: маршруты, переключение роли, меню и типизированный клиент. #54 реализует `/submit` (подача), `/my` (свои обращения с пагинацией) и `/my/:complaintId` (статус, следующий шаг, история и итог). #55 добавляет `/queue` и `/queue/:complaintId`: фильтры, назначение, статусы, комментарии, уточнение и решение. Сводка `/summary` ожидает #56. Выбор роли — демонстрация, не защищённый вход. Сервер получает `X-Demo-User` и самостоятельно проверяет права; скрытие пунктов меню не заменяет авторизацию.

Для пути автора запустите API (`npm --prefix api ci`, `npm --prefix api run build`, `npm --prefix api start`), затем фронтенд. Категории, обращения и регистрационный номер поступают с сервера; при ошибке отправки поля сохраняются. Необязательное тестовое вложение — фиксированный синтетический файл-заглушка: отправляются только его метаданные, содержимое не загружается.

Путь уточнения: руководитель открывает карточку → пишет вопрос и запрашивает уточнение → сотрудник открывает то же обращение в своих → отвечает в форме уточнения → руководитель видит ответ и продолжает обработку. Допустимые статусы генерируются в `src/api/policy.ts` из `x-status-transitions` контракта. Завершённые обращения не предлагают действий изменения; для решения и отказа объяснение обязательно. Ошибка записи сохраняет текст и предлагает обновить карточку. Фильтры очереди применяются сервером; даты означают начало/конец выбранного дня в часовом поясе браузера и передаются как UTC-моменты.

`useSession()` предоставляет текущую роль и API-клиент. При смене роли создаётся новый клиент и сбрасывается дерево страницы, чтобы не переносить данные предыдущей роли. Ошибки API возвращаются как `ApiError`: HTTP-код, код контракта, сообщение и ошибки полей. Сетевые ошибки имеют код `NETWORK_ERROR`.

Типы в `src/api/schema.d.ts` генерируются из принятого `contracts/api.yaml`. Не редактировать вручную:

```sh
npm --prefix web run api:generate
npm --prefix web run api:check
```

`npm run test` проверяет актуальность типов и запускает Vitest/Testing Library. Приёмочный вход `tests/acceptance/50-web-shell.test.mjs` запускает тот же набор в полном `hk check`. Запросы в тестах подменяются локальными ответами, сеть не требуется. Стили оболочки находятся в `src/shell.css`; каталог `src/styles/` оставлен для команды дизайна.
