# API

Fastify + TypeScript, Node.js 22+. Публичный `GET /health` и демо-API обращений.

Из корня репозитория:

```sh
npm --prefix api ci
npm --prefix api run test
npm --prefix api run build
npm --prefix api start
```

По умолчанию сервер слушает `http://127.0.0.1:3000`. `HOST` и `PORT` можно
задать переменными окружения. Для разработки: `npm --prefix api run dev`.

`GET /health` возвращает HTTP 200 и JSON
`{"status":"ok","version":"0.1.0"}`. Версия читается из `api/package.json`.
`buildApp()` создаёт независимый экземпляр без открытия порта; приёмочные тесты
проверяют и Fastify injection, и настоящий HTTP-запрос на свободный локальный порт.

При старте каждый экземпляр API получает собственное хранилище в памяти и
20 обращений A-001..A-020 из `api/data/seed.json`, перенесённых из `docs/dataset.md`.
Повторный `store.seed()` добавляет только отсутствующие записи. Чтение возвращает
копии: изменение результата чтения не повреждает хранилище.

**Ограничение демо:** данные живут в памяти процесса. Перезапуск сбрасывает изменения
и восстанавливает исходные 20 обращений; это не постоянная база данных.
Для сохранения между перезапусками можно задать `PERSIST_FILE` — абсолютный путь
или путь относительно рабочей папки к JSON-снимку. Без переменной файлы не создаются.
При записи сначала создаётся временный файл рядом со снимком, затем выполняется
атомарное переименование; при ошибке старый снимок и память не изменяются. Нужны
права записи на папку, путь с пробелами и кириллицей поддерживается.
Перед восстановлением повреждённого, пустого или несовместимого снимка исходный
файл переименовывается в `<имя>.bak-<UTC-метка>-<UUID>` рядом с ним. Метка не
содержит двоеточий; UUID различает даже запуски в одну миллисекунду. После этого
API загружает seed и записывает новый снимок. Предупреждение `PERSIST_FILE_INVALID`
содержит JSON с уровнем `warn`, исходным путём, путём копии и причиной `json_parse`
или `schema_validation`, без текста пользовательских данных.
Если резервную копию создать нельзя, API запускается с seed в памяти, пишет
ошибку `PERSIST_BACKUP_FAILED` и сохраняет исходный файл нетронутым. Операции
записи возвращают 500 без изменения памяти, пока резервное переименование не
удастся; каждая запись повторяет попытку. После исправления прав следующая запись
сначала сохранит оригинал, затем запишет данные. Ошибки чтения файла не скрываются.
Формат проверяется по текущему контракту без миграций. Старые копии автоматически
не удаляются: восстановление и очистка выполняются оператором.
Это режим **одного процесса-писателя**, не замена общей БД: нельзя одновременно
запускать несколько API с одним `PERSIST_FILE`. Для сдачи не включайте рабочий
снимок в архив или коммит, храните его вне репозитория.
Даты создания, ответа и закрытия — фиксированные вымышленные UTC-значения для
демонстрации будущей аналитики, а не показатели реальной компании.
Реализованы `GET /session`, `GET /reference-data`, `POST /complaints`,
`GET /complaints`, `GET /complaints/:id`, `PATCH /complaints/:id/assignment`.
Список поддерживает совместные фильтры `departmentId`, `categoryId`, `status`,
`type`, `dueAfter`, `dueBefore`, `overdue`, `queue`, поиск по словам `q` и
пагинацию `limit`/`offset`. Границы срока включительные, сравнение в UTC.
Просрочка вычисляется при чтении; завершённые обращения не просрочены.
Итоговое количество считается после ограничения прав и фильтров, до пагинации.
Сортировка стабильна: дата создания по убыванию, затем ID по возрастанию.

`q` ищет в номере, описании, предлагаемом решении и тексте комментариев.
Регистр не учитывается, `е` и `ё` равнозначны в запросе и данных. Слова
разделяются пробельными символами и объединяются через И: каждое должно
встретиться хотя бы в одном из этих полей; порядок слов не важен. Например,
`q=мешки склад` найдёт описание про склад с комментарием о мешках. Слова ищутся
как буквальные фрагменты без регулярных выражений и морфологии. Пустой набор
слов не ограничивает выборку. Максимум — 200 символов по контракту; превышение
возвращает 422. Проверка автора выполняется до поиска, фильтров и подсчёта total.
Исходный текст не переписывается; поиск не меняет существующий порядок сортировки.

`GET /summary` доступен только администратору: количество по типам, доля
завершённых (implemented/rejected/closed), среднее время первой реакции
руководителя в часах и категории с двумя и более обращениями. Неотвеченные
исключаются из среднего; при отсутствии ответов среднее равно `null`.
Это расчёт по вымышленным данным, не реальные показатели компании.

Жизненный цикл: `PATCH /complaints/:id/status` (200),
`POST /complaints/:id/comments` и `POST /complaints/:id/decision` (201).
Переходы проверяются по таблице контракта. Запрос уточнения переводит запись в
ожидание ответа автора; ответ возвращает её на рассмотрение. Решение требует
непустого объяснения, после него запись нельзя менять. Комментарии и история
хранят автора и UTC-время; первая реакция фиксируется только действием руководителя.
Ошибки не оставляют частично изменённых данных или истории.

Для бизнес-методов передайте заголовок `X-Demo-User`: `employee-1`, `employee-2`,
`manager-1` или `admin-1`. Это **имитация выбора роли для локального демо**, не
промышленная аутентификация. Сотрудник создаёт и видит свои записи; руководитель
видит все, включая очередь `queue=unassigned`, и может назначить ответственного;
администратор читает записи. Автор и подразделение определяются сервером.

Тела запросов проверяются по `contracts/api.yaml` (этот файл нужен при запуске).
Неверные поля не изменяют данные. Вложения — только метаданные заглушек, без
загрузки файлов. Категория `no_rule_demo` демонстрирует отсутствие ответственного.

По умолчанию JSON-тело ограничено 64 КиБ: превышение возвращает 413
`PAYLOAD_TOO_LARGE` до проверки полей. Длины описания, предлагаемого решения
и комментария берутся из `maxLength` соответствующих схем контракта, без
отдельных констант. При превышении ответ 422 `VALIDATION_ERROR` содержит
`details` с именем поля и допустимым пределом в русском сообщении. Пустое или
пробельное описание отклоняется; у принятых текстов обрезаются крайние пробелы.
Неправильный JSON возвращает 400 `BAD_REQUEST`, неподдерживаемый Content-Type —
415 `UNSUPPORTED_MEDIA_TYPE`, без стека или частичного изменения данных.

Запросы POST/PATCH ограничены отдельным окном для каждого `X-Demo-User`:
по умолчанию 30 попыток за 60 секунд. Настройки: `RATE_LIMIT_MAX` (целое >= 0)
и `RATE_LIMIT_WINDOW_S` (целое >= 1). После исчерпания API возвращает 429,
`RATE_LIMITED` и `Retry-After` в секундах, не выполняя запись. Все ответы записи
содержат `X-RateLimit-Limit` и `X-RateLimit-Remaining`; учитываются также неудачные
попытки. GET не расходует лимит. Неизвестные идентификаторы используют общий
ограниченный резервный счётчик. `NODE_ENV=test` или `RATE_LIMIT_MAX=0` отключает
ограничение (значения заголовков тогда 0). Счётчики существуют только в памяти
экземпляра API: между процессами они не синхронизируются, при перезапуске исчезают.

Все ответы содержат `X-Content-Type-Options: nosniff`,
`Referrer-Policy: no-referrer` и `Cache-Control: no-store`, включая ошибки.
Для отдельного адреса фронтенда задайте `CORS_ORIGINS` — точные HTTP(S) origins
через запятую, например `https://employee-feedback.vercel.app,http://localhost:5173`.
Пути, завершающий `/`, логин/пароль и `*` запрещены; неверная настройка останавливает
запуск. Пробелы вокруг элементов игнорируются. Без переменной (или при пустом
списке) CORS выключен. Разрешённый источник получает свой
`Access-Control-Allow-Origin`; preflight OPTIONS возвращает 204 с методами
GET/POST/PATCH/OPTIONS и заголовками Content-Type, X-Demo-User, X-Request-Id.
Браузеру доступны также Retry-After, X-RateLimit-Limit, X-RateLimit-Remaining,
X-Request-Id. Cookie credentials не разрешаются. Чужой Origin не получает CORS,
но сам запрос на сервере выполняется с обычной проверкой роли: CORS не является
авторизацией и не превращает демо-заголовок в безопасный механизм входа.

### Похожие обращения и подсказка категории (#121)

`GET /complaints/similar?text=...` возвращает до трёх обращений с номером,
категорией, статусом и оценкой 0..1 (сходство Жаккара по множествам слов
`description` + `proposedSolution`). Текст приводится к нижнему регистру, `ё` → `е`,
токены — последовательности букв и цифр Unicode, стоп-слова отбрасываются.
Стоп-слова: и, в, во, на, не, что, это, как, а, но, или, по, к, с, со, у, о, об, от,
до, из, за, для, при, про, же, ли, бы, то, так, там, тут, он, она, они, оно, мы, вы,
я, его, ее, их, наш, ваш, быть, был, была, были, было, есть, можно, нужно, очень,
также, еще, уже, всех, все, всё, чтобы, если, когда, который, которые, этот, эти, такой.
Порядок: оценка по убыванию, затем `createdAt` по убыванию, затем `id`. Текст короче
10 символов (после обрезки пробелов), только стоп-слова или нет совпадений — `{"items":[]}`
и 200. Доступ по `api/concept/access.md`: сотрудник ищет только среди своих
обращений, руководитель и администратор — в обычной области списка; описание,
автор и комментарии в ответ не попадают.

`GET /complaints/suggest-category?text=...` работает офлайн: сравнивает текст с
записанными примерами из `api/data/ai-fixtures.json` (сходство Жаккара ≥ 0,3) и
возвращает `{category: {id, name}, source: "demo-fixture"}`. Если уверенного
совпадения нет или текст короче 10 символов — `{category: null, source: "none"}`.
Сети и ключей нет. Оба эндпоинта: без `text` или длиннее 5000 символов — 422.
