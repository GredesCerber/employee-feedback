# Идея: простая сводка и повторяющиеся темы без ИИ

- **Автор:** GredesCerber
- **Тип:** функция

## Проблема
ТЗ хочет выявлять повторяющиеся проблемы и показывать результаты рассмотрения (п. 1.3, 2.7). В датасете есть повторяющиеся темы: например, передача работы между подразделениями (A-001) и поиск актуальной версии документа (A-019).

## Идея
Сводка считается запросом по сохранённым обращениям, без внешних сервисов: число по типам, доля закрытых (закрытые / все, 0 при пустом наборе), среднее время первого ответа по обращениям, на которые уже ответили, и топ категорий по количеству. Повторяющаяся тема в MVP: категория, в которой несколько обращений за период. Формулы описаны в контракте, чтобы фронт и бэк считали одинаково. Смысловая кластеризация текстов остаётся в развитии как отдельная техническая задача.

## Проверка по манифесту
- Связь с ТЗ (пункт): п. 2.4 (аналитика), 2.7 (показатели: время до первого ответа, доля рассмотренных)
- Можно показать на синтетических данных: да, шаг 6 демо; на расширенном датасете `design/demo/dataset-extra.md` ожидаемое среднее время первого ответа 5 ч 30 мин
- В MVP или в развитие, почему: простая сводка в MVP (R7, should); кластеризация по смыслу в развитие

## Риски и допущения
- Допущение: нужно уточнить, считаем ли реализованное и отклонённое закрытыми (в контракте #62 это открытый вопрос).
- Риск: категория как «тема» грубее смысла; честно говорим об этом на демо.
- В развитие: поиск похожих обращений в момент подачи, выгрузка в BI (описание).
