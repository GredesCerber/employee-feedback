# Идея: маршрутизация по категории с запасной очередью

- **Автор:** GredesCerber
- **Тип:** функция

## Проблема
ТЗ просит не терять обращения и передавать их ответственному «по заданным правилам» (п. 1.3, 2.5). Правило есть не для каждой категории (в датасете есть темы без очевидного владельца, например A-002 «Информационная прозрачность»), и обращение без владельца легко «зависает».

## Идея
Таблица правил «категория → ответственный руководитель» хранится как справочник. При создании обращения бэкенд ищет правило. Если правило нашлось, ответственный и срок (`createdAt` плюс срок категории) назначаются сразу. Если не нашлось, обращение всё равно регистрируется с `routing.queue = unassigned` и причиной `no_rule`, видно всем руководителям, и любой из них может назначить ответственного вручную. Регистрация и назначение пишутся одной транзакцией вместе с событиями истории.

## Проверка по манифесту
- Связь с ТЗ (пункт): п. 1.3, 2.3 (шаг 3), 2.5
- Можно показать на синтетических данных: да, шаг 2 сценария демо: одно обращение с правилом, другое без
- В MVP или в развитие, почему: в MVP (R2, must); правила только из справочника, редактор правил для админа в развитие

## Риски и допущения
- Допущение: список руководителей и правила синтетические.
- Риск: руководители могут не заметить очередь; на демо показываем счётчик «без ответственного» и фильтр `queue=unassigned`.
- В развитие: автоназначение по нагрузке, интеграция с оргструктурой Битрикс24 (требует уточнения источника данных).
