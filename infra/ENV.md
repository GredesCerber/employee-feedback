# Переменные окружения

Все настройки решения через env собраны здесь. Таблицу сверяет с кодом тест
`tests/acceptance/105-env-docs.test.mjs` (вручную: `node infra/check-env.mjs`).

Правила:

- Читаете в коде новую переменную — добавьте строку в таблицу.
- Переменная ещё не читается кодом, но нужна для будущей задачи — оставьте строку и напишите в «Статус» слово «планируется».
- В `api/.env.example` и `web/.env.example` значения всегда пустые. Секреты и ключи в репозиторий не кладём, только в локальный `.env` (он в `.gitignore`).
- Системные `PATH` и `npm_execpath` выставляют ОС и npm, они здесь не описываются.

Все значения по умолчанию рассчитаны на локальное демо: ни одна переменная не обязательна.

Для живого перевода сообщений нужен `ANTHROPIC_API_KEY`. Docker Compose передаёт его API из окружения/корневого `.env`, а `AI_MODEL` выбирает модель; в клиентскую сборку ключ не попадает. Без ключа `POST /complaints/{complaintId}/translations` возвращает `503 TRANSLATION_UNAVAILABLE`, оригинал сообщения остаётся доступным. Для обычного запуска, карты и трёх языков ключ не требуется. Не добавляйте `.env` в Git.

## Render и Vercel

Для Render задайте `HOST=0.0.0.0`, `NODE_ENV=production`, `NODE_VERSION=22`;
`PORT` платформа передаёт сама. Остальные лимиты можно оставить по умолчанию.
В Vercel `VITE_API_BASE_URL` — HTTPS URL API без `/api` и завершающего `/`.
Значения `VITE_*` публичны: ключи и пароли туда передавать нельзя.
После изменения API env перезапустите API; после смены Vite env пересоберите веб.
Для отдельных доменов требуется принятая #94 и точный origin веба в `CORS_ORIGINS`.
Подробные шаги и откат — в [deploy/README.md](deploy/README.md).
