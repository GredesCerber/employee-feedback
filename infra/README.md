# Запуск и демонстрация

Система обратной связи и предложений сотрудников ГК «Модус Трейд» (MVP хакатона). Все данные синтетические.

## Запуск одной командой

Без Docker, с Node.js >=22.12.0 и npm:

```sh
node infra/run-demo.mjs
```

При отсутствии `node_modules` устанавливает зависимости из lockfile, собирает API
и веб, выбирает свободные локальные порты и печатает адрес браузера. Веб использует
`/api` на своём адресе; локальный сервер проксирует запросы на выбранный API-порт.
Ctrl+C останавливает оба процесса. Не запускает внешние сервисы и не публикует сайт.

Флаги: `--api-port 3000`, `--web-port 5173`, `--no-install` (зависимости уже установлены),
`--seed-reset` (игнорировать `PERSIST_FILE`, запустить исходный seed в памяти, не удаляя файл),
`--dry-run` (JSON-план без выполнения), `--help` (справка). При занятом явно указанном
порте запуск завершается ошибкой, второй сервер останавливается. Если порты не заданы,
выбираются свободные. Для чистого клона нужен доступ к npm при установке пакетов.
На Windows вызывается `node npm-cli.js`, а не `npm.cmd` через оболочку.

### Существующий вариант с Docker

Нужен только Docker (Docker Desktop на Windows/macOS или Docker Engine с плагином Compose на Linux).

```sh
docker compose up --build
```

- Приложение: http://localhost:8080
- API за тем же адресом: http://localhost:8080/api/health
- Другой порт: `WEB_PORT=9000 docker compose up --build` (PowerShell: `$env:WEB_PORT=9000; docker compose up --build`).
- Остановить и убрать контейнеры: `docker compose down`.

Что поднимается:

| Сервис | Образ | Что делает |
|---|---|---|
| `api` | `infra/api.Dockerfile` (Node 22, Fastify) | API по `contracts/api.yaml`, демо-данные из `api/data/seed.json` в памяти |
| `web` | `infra/web.Dockerfile` (сборка Vite → nginx) | Фронтенд, прокси `/api/*` → `api:3000`, все маршруты приложения отдают `index.html` |

Данные хранятся в памяти API: после `docker compose restart api` всё возвращается к исходному seed. Это удобно для повторного показа.

## Переменные окружения

Все настройки через env (имя, где используется, значение по умолчанию, обязательность) описаны в [ENV.md](ENV.md). Сверка с кодом: `node infra/check-env.mjs`.

## Демо-логины ролей

Входа по паролю нет: роль выбирается переключателем в шапке приложения (сервер получает заголовок `X-Demo-User` и сам проверяет права). Это **имитация входа**, а не защищённая аутентификация.

| Логин | Роль | Кто это в демо | Что показывать |
|---|---|---|---|
| `employee-1` | Сотрудник | Сотрудник закупок (автор A-001 и др.) | Подача обращения, «Мои обращения», ответ на уточнение, итог |
| `employee-2` | Сотрудник | Сотрудник бухгалтерии | Видит только свои обращения (чужие отвечают 404) |
| `manager-1` | Руководитель | Руководитель закупок | Очередь, фильтры и просроченные, назначение, статусы, уточнение, решение и мотивированный отказ |
| `admin-1` | Администратор | Администратор демо | Сводка: типы, доля закрытых, время первого ответа, повторяющиеся темы |

## Сценарий показа (3 минуты)

1. `employee-1` подаёт обращение: тип, категория, описание, предполагаемое решение, вложение-заглушка → получает номер.
2. Обращение автоматически назначено руководителю по правилу категории; категория «без ответственного (демо)» попадает в общую очередь.
3. `manager-1` берёт в работу и запрашивает уточнение; `employee-1` отвечает в карточке.
4. `manager-1` фиксирует решение или мотивированный отказ (без объяснения сохранить нельзя); автор видит итог.
5. `manager-1` фильтрует очередь по подразделению, категории, статусу и сроку, находит просроченные.
6. `admin-1` открывает сводку.

## Реализовано

- Подача обращения с типом, категорией, описанием, предполагаемым решением и номером регистрации (R1).
- Назначение ответственного по категории и запасная очередь без ответственного (R2).
- Статусы по допустимым переходам контракта, сроки, история, комментарии, запрос и ответ на уточнение (R3).
- Решение и мотивированный отказ, видимые автору (R4).
- Проверка прав на сервере для каждого запроса: сотрудник, руководитель, администратор (R5).
- Поиск и фильтры очереди, признак просрочки (R6).
- Сводка администратора: типы, доля закрытых, время первого ответа, повторяющиеся категории (R7).
- Запуск одной командой в Docker (этот документ).

## Имитация

- **Вход:** выбор демо-пользователя вместо логина и пароля.
- **Вложения:** фиксированный файл-заглушка, передаются только метаданные, содержимое не загружается.
- **Хранилище:** данные в памяти процесса, без БД.
- **Уведомления и интеграции:** уведомлений автору и ответственным, обмена с Битрикс24 и 1С УТ нет, в демо только описываются.

## План

- Настоящая аутентификация (SSO через Битрикс24) и разграничение по оргструктуре.
- Постоянное хранилище: PostgreSQL для обращений и объектное хранилище (S3-совместимое) для файлов, загрузка больших вложений.
- Уведомления в приложении, по почте и в Битрикс24; передача принятых предложений задачами в Битрикс24.
- Анонимная подача со скрытием имени от ответственного (описано в `api/concept/access.md`).
- Подсказка похожих обращений и демо-помощник на ИИ при подаче (идеи `web/concept/ideas/`).
- Опросы, NPS и клиентская обратная связь (R13).

## Выкладка на хостинг

Подойдёт любой сервер или VPS с Docker: склонировать репозиторий и выполнить `docker compose up --build -d`, открыть порт `WEB_PORT`. Внешних сервисов и секретов не требуется. Перед реальной выкладкой нужны HTTPS (обратный прокси с сертификатом) и настоящая аутентификация: демо-переключатель ролей не защищает данные.

## Проверка перед сдачей

Из корня репозитория: `node infra/check-submission.mjs`. Сеть не используется.
Скрипт проверяет текущие отслеживаемые git-файлы: размер до 100 000 000 байт,
похожие на ключи строки, непустые значения `.env*` (кроме `.env.example`),
обязательные документы, инструкцию запуска и сценарий демо. `node_modules` и
`dist` не учитываются; символические ссылки не читаются и отмечаются ошибкой.
Выводит топ-10 файлов по размеру и ссылки из README/docs. У ссылок скрываются
учётные данные, параметры и фрагменты; доступность из чужого аккаунта нужно проверить вручную.
Любой пункт ✗ даёт код выхода 1. Значения найденных ключей не печатаются — только
путь, номер строки и категория. Это эвристическая проверка, она не доказывает
отсутствие всех возможных секретов и не отправляет материалы жюри.
