# Эскиз API: ресурсы, операции и роли

Краткий обзор для чтения людьми. Источник правды остаётся [contracts/api.yaml](../api.yaml) (OpenAPI 3.1); если здесь что-то расходится с контрактом, прав контракт. Модель данных: [domain.md](../../api/concept/domain.md). Права по ролям: [access.md](../../api/concept/access.md).

## Ресурсы

| Ресурс | Что это | Основные поля |
|---|---|---|
| Сессия (`/session`) | Демо-пользователь, выбранный заголовком `X-Demo-User` | `id`, `name`, `role`, `departmentId` |
| Справочники (`/reference-data`) | Категории, подразделения, возможные ответственные | `categories[assigneeId, dueInDays]`, `departments`, `assignees` |
| Обращение (`/complaints`, `/complaints/{id}`) | Центральная сущность | тип, категория, описание, статус, ответственный, сроки, комментарии, история, решение |
| Назначение (`/complaints/{id}/assignment`) | Ручное назначение ответственного | `assigneeId` |
| Статус (`/complaints/{id}/status`) | Прямой переход между статусами | `status` |
| Комментарии (`/complaints/{id}/comments`) | Комментарий, запрос уточнения, ответ автора | `kind`, `text` |
| Решение (`/complaints/{id}/decision`) | Итог: реализовано, отклонено или закрыто | `outcome`, `explanation`, `actions` |
| Сводка (`/summary`) | Аналитика для администратора | число по типам, доля закрытых, время первого ответа, повторяющиеся темы |

## Операции и роли

| Операция | Метод и путь | Роли | Успех | Ошибки |
|---|---|---|---|---|
| `getSession` | GET `/session` | сотрудник, руководитель, администратор | 200 | 400, 401, 403, 422, 500 |
| `getReferenceData` | GET `/reference-data` | все три (сотруднику список ответственных пуст) | 200 | 400, 401, 403, 422, 500 |
| `createComplaint` | POST `/complaints` | сотрудник | 201 | 400, 401, 403, 413, 415, 422, 500 |
| `listComplaints` | GET `/complaints` | все три (сотрудник видит только свои) | 200 | 400, 401, 403, 422, 500 |
| `getComplaint` | GET `/complaints/{id}` | все три (сотрудник только свои, чужое 404) | 200 | 400, 401, 403, 404, 422, 500 |
| `assignComplaint` | PATCH `/complaints/{id}/assignment` | руководитель | 200 | 400, 401, 403, 404, 409, 413, 415, 422, 500 |
| `changeComplaintStatus` | PATCH `/complaints/{id}/status` | руководитель | 200 | 400, 401, 403, 404, 409, 413, 415, 422, 500 |
| `addComment` | POST `/complaints/{id}/comments` | сотрудник (свои; ответ на уточнение), руководитель (комментарий и запрос уточнения) | 201 | 400, 401, 403, 404, 409, 413, 415, 422, 500 |
| `recordDecision` | POST `/complaints/{id}/decision` | руководитель | 201 | 400, 401, 403, 404, 409, 413, 415, 422, 500 |
| `getSummary` | GET `/summary` | администратор | 200 | 400, 401, 403, 422, 500 |

Фильтры списка (`listComplaints`): `departmentId`, `categoryId`, `status`, `type`, `dueAfter`, `dueBefore`, `overdue`, `queue` (`assigned` / `unassigned`), `q` (поиск по тексту), `limit`, `offset`.

## Единые правила

- **Личность:** заголовок `X-Demo-User`; роль и подразделение определяет сервер. Это имитация входа для демо, не защищённая аутентификация.
- **Ошибки:** один формат `{ code, message, details? }`. Порядок проверок: 401 (кто вы), 403 (что вам можно), 404 (видимость, для сотрудника чужое обращение неотличимо от несуществующего), 422 (поля), 409 (недопустимый переход или завершённое обращение).
- **Атомарность:** каждое изменение вместе с событием журнала записывается целиком или не записывается.
- **Данные:** только синтетические, вложения только метаданные файлов-заглушек.

## Покрытие сценария демо

| Шаг демо | Операции |
|---|---|
| 1. Сотрудник подаёт обращение (R1, R5) | `getSession`, `getReferenceData`, `createComplaint` |
| 2. Автоназначение и запасная очередь (R2) | `createComplaint`, `getComplaint`, `listComplaints` (`queue=unassigned`), `assignComplaint` |
| 3. Статус, уточнение, ответ автора (R3) | `changeComplaintStatus`, `addComment`, `getComplaint` |
| 4. Решение и мотивированный отказ (R4) | `recordDecision`, `getComplaint` |
| 5. Фильтры и просрочка (R6) | `listComplaints`, `getComplaint` |
| 6. Сводка администратора (R7) | `getSummary` |

Каждый из шести шагов покрыт хотя бы одной операцией; ту же привязку хранит `x-demo-flow` в контракте.

## Что не входит в MVP

- Анонимная подача, реальная загрузка файлов, уведомления, редактирование категорий и правил маршрутизации, интеграции с 1С УТ и Битрикс24 (описаны как развитие в [access.md](../../api/concept/access.md) и [интеграциях](../../docs/research/integrations.md)).
