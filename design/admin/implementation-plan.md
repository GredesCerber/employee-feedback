# Декомпозиция реализации

Это предложения задач после согласования спецификации #305, не созданные Issues
и не разрешение менять продукт в текущем PR. Текущие #287/#288 остаются точками
согласования, #290 про реальные вложения не входит в эту работу.

Каждая строка ниже относится к одной зоне. Имена прав и форматы запросов должны
сначала попасть в контракт. Для каждой `risk:high` реализации нужна отдельная
задача `tests_for`: её выполняет другой исполнитель, затем тесты переносятся
без изменения по правилам harness. Новые приемочные тесты и изменение старых
должны быть заранее согласованы в постановке соответствующей задачи.

Для contracts изменение формата не должно быть механическим снятием защиты:
сначала согласуется совместимость, миграция seed и существующих `x-roles`, затем
тесты и реализации. Не использовать текущий `X-Demo-User` как основу настоящего входа.

Риск W1/W3/W4 нужно пересмотреть при конкретной постановке: если в них переносится
реальная логика авторизации или существенное управление данными, повысить риск до
high и добавить независимую задачу на тесты. `med` здесь означает UI поверх
серверной политики, не разрешение ослаблять требования к защите.

## Очерёдность и точки решения

1. Капитан отвечает на вопросы из [navigation.md](navigation.md), утверждает
   модель роли, регистрации и сброса. После этого C1/C2 и независимые тесты.
2. Серверная основа A1/A2, экраны W1. Наличие меню не означает, что API защищён.
3. C3/A3 и W3/W4, затем демо-пакет I1 и Q1. Журнал закладывается вместе
   с изменением доступа, не добавляется после скрытого режима preview.
4. До защиты показать только фактически завершённые возможности. Несделанное
   остаётся в плане, при отсутствии новой аутентификации демонстрировать текущую
   имитацию честно, без выдуманных паролей.

## Разделение приёмки

- #305: документы, макеты 360/1280, наблюдения по состояниям/фокусу, без продукта.
- contracts/API: реальные полномочия, хранилище, сессии, аудит и отказ API.
- web: отображение серверных прав, маршруты, состояния и работа с клавиатурой.
- infra: воспроизводимый демо-набор, файл доступов и инструкция.
- e2e: независимые приёмочные и итоговые интеграционные сценарии.

Приёмка макета не засчитывается как реализация любой из перечисленных задач.
