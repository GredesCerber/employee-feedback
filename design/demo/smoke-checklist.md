# Проверка демо перед защитой

За 15 минут до выступления один человек проходит чек-лист на ноутбуке, с которого будет показ. Если шаг не сходится, смотрим «План Б». Сценарий взят из `docs/tz-analysis.md` (раздел 1), данные из синтетического датасета `api/data/seed.json` (20 обращений A-001…A-020).

## Подготовка (за 15 минут)

1. Запустить демо одной командой с чистыми данными:

```sh
node infra/run-demo.mjs --seed-reset
```

2. Открыть адрес из вывода команды в браузере, проверить, что `/api/health` на том же адресе отвечает `ok`.
3. Закрыть лишние вкладки и уведомления, включить масштаб 100–125 %, чтобы жюри видело текст.
4. Держать второй терминал открытым в корне репозитория для команд из «Плана Б».

## Чек-лист

Роль выбирается переключателем в шапке (вход имитируется, пароля нет).

| Шаг | Кто и что делает | Данные из датасета | Ожидаемый результат |
|---|---|---|---|
| 1 | `employee-1` (Сотрудник закупок) подаёт обращение | Тип «Проблема», категория «Межотдельное взаимодействие», описание «Согласование заявок между закупками и проектированием занимает больше недели», предлагаемое решение «Общий чат и срок ответа 2 дня», вложение-заглушка | Подтверждение с номером A-021 (в seed 20 обращений), обращение есть в «Моих обращениях» со статусом «Новое» |
| 2 | Проверяем автоназначение и запасную очередь | A-021 по правилу категории уходит руководителю `manager-1` (Руководитель закупок); второе обращение с категорией «Категория без ответственного (демо)» | В карточке A-021 виден ответственный и срок (7 дней); второе обращение без ответственного попадает в общую очередь руководителя |
| 3 | `manager-1` берёт A-021 в работу и запрашивает уточнение, `employee-1` отвечает в карточке | Вопрос «В каких проектах задержка больше всего?», ответ «ЖК Северный и склад на Красноярском тракте» | История статусов: «Новое» → «На рассмотрении» → «В работе» → «Ожидает уточнения» → «На рассмотрении» (после ответа автора обращение возвращается на рассмотрение); вопрос и ответ видны в комментариях |
| 4 | `manager-1` закрывает A-021 решением, а A-001 мотивированным отказом | Решение «Ввели срок ответа 2 рабочих дня»; отказ с объяснением; без объяснения кнопка не сохраняет | `employee-1` видит у A-021 статус «Реализовано» с решением, у A-001 «Отклонено» с причиной; пустое объяснение отклоняется с подсказкой |
| 5 | `manager-1` фильтрует очередь | Подразделение «Закупки», категория «Межотдельное взаимодействие», статус «Новое», флажок «просроченные» | Список сужается до обращений закупок (A-001, A-002, A-020 и новые); просроченные помечены (у seed фиксированные даты в прошлом, поэтому открытые обращения просрочены) |
| 6 | `admin-1` открывает сводку | Все 20+ обращений датасета | Обращения по типам, доля закрытых (в seed закрыты A-004, A-008, A-017, A-018), среднее время первого ответа, повторяющиеся категории (например, «Корпоративная среда») |

После прогона перезапустить демо с `--seed-reset`, чтобы на защите начать с чистых данных.

## План Б

| Сбой | Как узнать | Что делаем |
|---|---|---|
| API не стартует | В выводе `run-demo` ошибка API, `/api/health` не отвечает | Остановить Ctrl+C, пересобрать API `npm --prefix api run build` и снова запустить `node infra/run-demo.mjs --seed-reset`. Если ошибка повторяется, поднять Docker-вариант `docker compose up --build` |
| Порт занят | `run-demo` пишет, что порт занят, или открывается чужое приложение | Запустить без явных портов `node infra/run-demo.mjs` (выберет свободные) или указать другие `node infra/run-demo.mjs --api-port 3100 --web-port 5200`, открыть новый адрес из вывода |
| Нет сети | Установка пакетов падает с ошибкой сети | Зависимости ставим заранее (`npm --prefix api ci`, `npm --prefix web ci`), на защите запускаем без установки `node infra/run-demo.mjs --no-install --seed-reset`. Внешних сервисов демо не использует |
| Веб не грузится | Белая страница или ошибка в консоли браузера, API при этом отвечает | Пересобрать веб `npm --prefix web run build` и перезапустить `node infra/run-demo.mjs --no-install`; запасной путь: dev-сервер `npm --prefix web run dev` при запущенном `npm --prefix api run dev` |
| Данные испорчены | После репетиции лишние обращения, сбитые статусы или номер не A-021 | Сбросить демо: Ctrl+C и `node infra/run-demo.mjs --seed-reset` (файл `PERSIST_FILE` игнорируется, исходный seed грузится в память); в Docker `docker compose restart api` |

Если не помогло ничего за 2 минуты: показываем заранее загруженные обращения датасета и проговариваем сценарий по слайдам, как предусмотрено в `docs/tz-analysis.md` («Запасной план»).

## Что говорим честно

Статусы совпадают со столбцом «В демо?» в `docs/tz-analysis.md`. Ничего из «имитации» и «плана» не называем работающей интеграцией.

| Функция | Статус | Что говорим |
|---|---|---|
| R1 Подача обращения | реализовано | Тип, категория, описание, предлагаемое решение и номер работают; файл пока заглушка, передаются только его метаданные |
| R2 Назначение ответственного | реализовано | Правило по категории и запасная очередь без ответственного |
| R3 Статусы, сроки, уточнения | реализовано | Переходы по контракту, сроки, история и комментарии |
| R4 Решение и мотивированный отказ | реализовано | Отказ без объяснения сохранить нельзя, автор видит итог |
| R5 Роли и доступ | реализовано | Права проверяет сервер на каждом запросе; вход при этом имитирован, анонимность пока в плане |
| R6 Поиск, фильтры, история | реализовано | Фильтры очереди и признак просрочки |
| R7 Аналитика | реализовано | Сводка администратора на данных датасета |
| R8 Уведомления | имитация | Уведомлений по почте и в Битрикс24 нет, только показ в интерфейсе или рассказ |
| R9 Концепция | реализовано | На слайдах: проблема, пользователи, сценарии, MVP и развитие |
| R10 Прототип интерфейса | реализовано | Работающий веб на основных экранах |
| R11 Техническая концепция | реализовано | На слайдах; интеграции с 1С и Битрикс24 только описаны |
| R12 Честная демонстрация | реализовано | Этот раздел и бейджи «Имитация» в интерфейсе |
| R13 Опросы, NPS, клиентская обратная связь | план | Направление развития после MVP |
| Вход по логину и паролю | имитация | Переключатель демо-пользователя вместо логина, нужен SSO через Битрикс24 |
| Вложения | имитация | Файл-заглушка, содержимое не загружается |
| Хранилище | имитация | Данные в памяти процесса, без БД |
| Интеграции с 1С УТ и Битрикс24 | план | Только описание в технической концепции |
| Постоянная БД и большие вложения | план | PostgreSQL и S3-совместимое хранилище |
| Анонимная подача | план | Описана в `api/concept/access.md` |
