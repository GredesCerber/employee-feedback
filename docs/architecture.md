## Схема

```
браузер ── [web: React + Vite, ru/en/kk] ──HTTP /api/*──► [api: Fastify/TypeScript]
                                                              │
                         ┌──────────────────┬─────────────────┼──────────────────────┐
                         ▼                  ▼                 ▼                      ▼
                 память процесса    PERSIST_FILE (JSON)   PostgreSQL           ИИ-провайдеры
                 + seed A-001..020  один писатель         DATABASE_URL          ИИ-цепочка: Gemini → xAI
                                                          таблица complaints    или Groq → Anthropic → правила

Битрикс24 (облачный) и 1С УТ — только описание и имитация в интерфейсе, реальных вызовов нет.
```

Кто кого вызывает:

- Веб ходит только в API по префиксу `/api`. Префикс снимает nginx (docker compose), локальный прокси `infra/serve-demo.mjs` или сам API (`rewriteUrl` в `api/src/app.ts`).
- API — единственное место, где проверяются личность, роль и видимость. Скрытые кнопки в вебе ничего не защищают.
- Хранилище — кэш в памяти (`api/src/store.ts`). Чтение всегда из памяти. Запись идёт дальше в БД, если задан `DATABASE_URL`, иначе в JSON-файл, если задан `PERSIST_FILE`, иначе только в память.

## Модули API

| Модуль | Что делает |
|---|---|
| `complaints.ts` | сессия, справочники, подача (в т.ч. анонимная), список с фильтрами и поиском, карточка, экспорт CSV, сводка, тренды |
| `lifecycle.ts` | назначение, смена статуса по `x-status-transitions`, уточнения, комментарии, решение с обязательным объяснением |
| `undo.ts` | откат последнего действия руководителя в окне `UNDO_WINDOW_S` (по умолчанию 600 с) |
| `notifications.ts` | лента событий для сотрудника и руководителя (5 видов), каждое помечено `simulated: true` — имитация email/Битрикс24 |
| `discovery.ts`, `search.ts` | похожие обращения, подсказка категории (ИИ или правила слов), поиск по фрагментам слов |
| `digest.ts`, `analytics.ts` | сводка за период (модель или шаблон), метрики и тренды |
| `translations.ts` | перевод сообщения через ИИ-цепочку (Gemini → xAI/Groq → Anthropic); без ключей — 503, оригинал доступен |
| `rate-limit.ts`, `security.ts` | лимит POST/PATCH (429 + `Retry-After`), CORS по `CORS_ORIGINS` |
| `demo.ts` | `POST /demo/reset` для администратора, выключается `DEMO_RESET_ENABLED=false` |
| `persistence.ts`, `pg-persistence.ts` | JSON-снимок с атомарной записью; PostgreSQL, одна JSONB-строка на обращение |

## Контракты

Источник истины — [`contracts/api.yaml`](../contracts/api.yaml): из него API берёт схемы валидации, а веб генерирует типы и `policy.ts`. Роли указаны в `x-roles` каждой операции.

| Метод | Путь | Зачем | Роли | Шаг демо |
|---|---|---|---|---|
| GET | /session | кто я: роль, подразделение | все | 1 |
| GET | /reference-data | категории, подразделения, ответственные | все | 1 |
| POST | /complaints | подать обращение (флажок `anonymous`) | сотрудник | 1 |
| GET | /complaints/suggest-category, /complaints/similar | подсказка категории, похожие обращения при подаче | все | 1 |
| GET | /complaints, /complaints/{id} | мои обращения / очередь, карточка с историей | все (сотрудник — только свои) | 2 |
| PATCH | /complaints/{id}/assignment, /status | назначить ответственного, сменить статус | руководитель | 2 |
| POST | /complaints/{id}/comments | комментарий, запрос и ответ на уточнение | сотрудник, руководитель | 2 |
| POST | /complaints/{id}/decision | решение или мотивированный отказ | руководитель | 3 |
| POST | /complaints/{id}/undo | откатить своё последнее действие | руководитель | 2 |
| POST | /complaints/{id}/translations | перевести сообщение | все | 2 |
| GET | /notifications | лента событий (имитация уведомлений) | сотрудник, руководитель | 2–3 |
| GET | /summary | сводка по категориям и срокам | администратор | 4 |
| GET | /summary/digest, /analytics/trends, /complaints/export | дайджест, тренды, CSV | руководитель, администратор | 4 |
| POST | /demo/reset | вернуть демо-данные к seed | администратор | — |
| GET | /health | проверка живости | все | — |

## Данные

- `Complaint`: внутренний id и номер `A-…`, тип (проблема/предложение), категория, подразделение, автор, признак `anonymous`, текст, предлагаемое решение, приоритет, ответственный, статус, срок, комментарии, история, решение, метаданные вложений, необязательная точка на карте. Справочные сущности: `User`, `Category`, `ReferenceData` (категории, подразделения, ответственные), `Comment`, `HistoryEvent`, `Decision`, `Attachment`, `GeoPoint`, `AnonymousActor` ([модель](../api/src/model.ts)).
- Анонимность — скрытие автора при показе: настоящий автор хранится для проверки доступа, руководитель и администратор видят «Аноним» (`x-anonymity` в контракте).
- Seed: 20 синтетических обращений A-001..A-020 ([seed.json](../api/data/seed.json), [описание](dataset.md)); `SEED_RELATIVE_DATES=1` сдвигает сроки к текущему дню.
- PostgreSQL: таблица `complaints`, одна JSONB-строка на обращение, сброс демо — `replaceAll` в одной транзакции ([pg-persistence.ts](../api/src/pg-persistence.ts)). Миграций схемы и реляционной модели пока нет.
- Только в памяти процесса: счётчики лимита запросов и стек отката, они не переживают перезапуск.

## Деплой

| Способ | Как | Хранилище |
|---|---|---|
| Локально без Docker | `node infra/run-demo.mjs` (свободные порты, прокси `/api`); `npm run demo:reset` — с чистого seed | `PERSIST_FILE` |
| Docker | `docker compose up`: nginx отдаёт веб на `:8080` и проксирует `/api/` в API | память или `PERSIST_FILE` |
| Единый сервис (Render) | `infra/hosted.Dockerfile`, `infra/render.yaml`: API сам отдаёт сборку веба (`WEB_ROOT`) | PostgreSQL по `DATABASE_URL` (Neon и др.) |
| Веб и API раздельно | Vercel + Render по [infra/deploy/README.md](../infra/deploy/README.md), `CORS_ORIGINS` с точным origin веба | PostgreSQL |

Все переменные окружения и значения по умолчанию — [infra/ENV.md](../infra/ENV.md). Ни одна не обязательна для локального демо; ключи (`ANTHROPIC_API_KEY`, `DATABASE_URL`) только в окружении, не в Git.

## Решения и почему

- Контракт OpenAPI — единый источник: API валидирует по нему, веб генерирует типы и права. Так фронт и бэк не расходятся, а тесты ловят несовпадение.
- Права проверяет только сервер, по порядку 401 → 403 → 404: чужое обращение для сотрудника неотличимо от несуществующего.
- Вход — имитация через `X-Demo-User`, а не SSO: ТЗ не требует реального подключения, а для показа нужен быстрый переход между ролями. Настоящий вход — OAuth облачного Битрикс24, план.
- Хранилище за одним интерфейсом (память → файл → PostgreSQL): локальное демо работает без БД, хостинг переживает перезапуски, код маршрутов один. JSONB-строка вместо таблиц — быстрее для хакатона; для пилота нужны миграции и реляционная схема.
- Анонимность как скрытие автора, а не его удаление: иначе невозможны уточнения и проверка «только свои».
- Внешние системы (Битрикс24, 1С УТ, email) только описаны и показаны как имитация с пометкой: реального обмена нет, и демо не должно выдавать его за готовый.
- ИИ необязателен: без ключей подсказка категории, дайджест и перевод работают по фикстурам и правилам (перевод без ключа — 503, оригинал доступен), сеть не нужна, демо воспроизводимо. Цепочка провайдеров: Gemini → xAI или Groq → Anthropic (если задан ANTHROPIC_API_KEY) → правила; переход к следующему — при ошибке или таймауте (AI_TIMEOUT_MS).
