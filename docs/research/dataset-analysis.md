## 4. Что из этого следует для продукта

**Категории (R1, R2).** Предлагаю укрупнить 18 категорий до 7, сохранив исходную как подкатегорию:

| Укрупнённая категория | Исходные категории | Ответственный по умолчанию |
|---|---|---|

Запасной путь (сценарий 2 датасета): если ответственный по категории не назначен, обращение попадает в общую очередь руководителя направления. Детали правил — в T13.

**Типы (R1).** Три типа: Проблема, Предложение, Отзыв. Отзыв не требует решения и закрывается после фиксации.

**Статусы (R3, R4).** Из датасета получается жизненный цикл:

Новое → На рассмотрении ⇄ Ожидает уточнения → В работе → Реализовано / Отклонено. Отзыв: Новое → Закрыто.

Отклонение обязательно с текстом причины (пример — A-017). Реализовано обязательно с описанием результата (A-004, A-008).

**Роли (R5).** Автор (любой сотрудник), ответственный (роль из таблицы выше), руководитель направления (запасная очередь, переназначение), администратор (категории и правила).

**Пробелы в данных (R6, R7).**
- Нет дат создания, первого ответа и закрытия. Без них нельзя показать просрочку и «среднее время первого ответа» из сценариев 5 и 6. Нужно дописать синтетические даты (связано с T26, расширением датасета).
- Нет поля «подразделение»: выводим его из роли автора.
- Нет сроков рассмотрения: предлагаем срок по приоритету (например, высокий — 2 рабочих дня, средний — 5, низкий — 10), согласовать в T13.
- Нет вложений: для демо нужен файл-заглушка.
